# グループ管理の仕様

管理の画面の「グループ管理」（`/management/groups`）の決まり。グループがファイルの権限で
どう扱われるか（下位のメンバーは上位のメンバーでもある、「全員」の扱いなど）は
`doc/files.md` の「グループ」を参照。

# グループ

* グループは部署にもプロジェクトにも使う。最上位のグループ（根）は複数作れる
* 持つもの: 名前、上位グループ、ラベル、メンバー（とグループ管理者）、状態（有効・利用停止）
* 名前は、同じ上位の下にある**有効なグループの間で**重ならないようにする。利用停止中の
  グループとは重なってよい（組織変更で、停止した「営業本部」と同じ名前で作り直せるように）
* 「全員」グループはシステムが作るもので、名前の変更・削除・利用停止・メンバーの編集はできない。
  上位グループにも選べない

# 画面

* 左にツリー、右に選んだグループの詳細。ツリーの先頭に「全員」を固定で出す
* 詳細は参照だけ。「編集」で編集の画面に移る
* 追加は、作る場所が分かる3か所から行う（`doc/design.md` の「ツリーに項目を足す操作」）
  * ツリーの末尾の「グループを追加」: 最上位に作る
  * ツリーの各行の「＋」: その行のグループの下に作る（PC だけ）
  * 詳細の「下位グループを追加」: そのグループの下に作る
* 上位グループは「全社 > 営業本部」のように最上位からの道筋で示す
* 下位グループのメンバーは「下位グループに所属するメンバー（◯人）」として閉じて出し、
  開くと30人ずつ読み込む。下までスクロールすると続きを読み足す。同じ人が複数の下位グループに
  いれば1行にまとめ、所属する下位グループを並べる

# 編集

* 名前・上位グループ・ラベル・メンバー（追加・外す・グループ管理者の切り替え）を、
  「保存する」でまとめて保存する。「キャンセル」ですべて取り消す
* メンバーの追加は、ダイアログで利用者を検索して選ぶ。複数を選んで一度に追加できる。
  候補に出すのはテナントの所属のうち有効・招待中の人（停止中の人は出さない）
* 上位グループには、自分自身と自分の下位、「全員」、利用停止中のグループを選べない

# ラベル

* グループに複数付けられる。部署の分類（本部・地域など）やプロジェクトの見分けに使う
* テナントごとのラベルの一覧を持ち、入力欄では一覧から候補を出す。一覧に無い名前を
  入力すると、新しいラベルとして一覧に加わる

# グループ管理者

* グループのメンバーのうち、グループ管理者の印を付けた人
* **自分が管理者のグループとその下位**（以下「範囲」）の編集を、テナントの管理者でなくても行える
  * 名前・ラベル・メンバー（グループ管理者の指定を含む）の編集
  * 範囲の中への下位グループの作成、範囲の中のグループの削除・利用停止・再開・移動
  * 自分が管理者であるグループそのものの利用停止・再開（終わったプロジェクトを自分で閉じられるように）
* ただし次はできない
  * 自分が管理者であるグループそのものの削除（戻せないので、テナントの管理者が判断する）
  * 範囲の外への移動（上位グループを範囲の外のグループにすること）。最上位のグループの作成
* 管理の画面には「グループ管理」だけを出す（利用者管理・組織設定はテナントの管理者だけ）
* ツリーと詳細も範囲の中だけを出す。範囲のいちばん上のグループを根として描き、「全員」は出さない
  （範囲の外を開いても見つからない扱いにする）
* テナントの管理者（オーナー・管理者）は、すべてのグループに対してすべての操作ができる

# 削除

* 編集の画面の「このグループを削除」から確認の画面に移って消す
* 下位グループもまとめて消す。確認の画面で、一緒に消える下位グループの数を示す
* 確認の画面には、他の機能（ファイルの共有設定など）への影響は書かない。機能が増えるたびに
  確認の画面へ注意を足していくことになるため
* 削除は戻せない。残しておきたいときは利用停止を使う

# 利用停止

組織変更や、終わったプロジェクトのグループを、消さずに残しておくための状態。

* 編集の画面の「利用停止」から確認の画面に移って停止する。確認の画面で、一緒に止まる下位の数を示す。
  削除と同じく、他の機能への影響は書かない
* 停止中のグループは編集できない（名前・上位・ラベル・メンバーとも）。普段のツリーにも出さない。
  削除・停止もできない（消したいときは再開してから消す）
* **下位グループもまとめて停止する。** 停止の操作をしたグループ（以下「起点」）と、その下位の
  すべての行に停止の印を書き込む。どの行も、自分の行だけで有効か停止中かが分かる
  （停止や再開は頻繁ではないので、下位をまとめて書き換える手間は問題にならない）
* 停止するとき、各行に次を記録する
  * 停止日時・停止した人（下位にも起点と同じものを入れる）
  * その時点の上位グループの名前の並び（スナップショット）。上位がその後に移動・改名されても、
    停止した時点の位置が分かるようにするため
  * 起点（どの停止の操作で止まったか）。起点の行には自分自身を入れる
* 先に下位だけを停止していたときは、その下位はその停止の起点のまま残す（上位の停止で書き換えない）
* **停止中のグループは、ファイルの権限の上では無いものとして扱う。** そのグループへの共有設定は
  効かず、メンバーもそのグループと上位グループのメンバーとして数えない（上位の詳細の
  「下位グループに所属するメンバー」にも出さない）。共有設定の行は残すので、再開すると元に戻る。
  新しく共有先にも選べない
  * 打ち消しは同じ主体への付与を取り消すだけで、他の主体からの権限は下げない（`doc/files.md`）。
    そのため主体ごと外しても権限が減るだけで、それまで見られなかったファイルが見えるようには
    ならない

## 再開

* 再開できるのは起点だけ。起点を再開すると、その停止の操作で一緒に止まった行を有効に戻す。
  先に別の操作で停止していた下位は、停止のまま残る
* 一緒に止まった下位の詳細には「『営業本部』と一緒に停止されています。再開は『営業本部』から
  行ってください」と出す
* 起点の上位が停止中のあいだは再開できない。「再開する」を押せなくし、「上位の『◯◯』が
  停止中のため再開できません。先に上位を再開してください」と出す
* 再開すると元の位置に戻る。同じ上位の下に同じ名前の有効なグループがあるときは再開できない
  （「同じ名前のグループがあるため再開できません」）

## 利用停止中のグループの画面

* ツリーの下の「利用停止中のグループ」から開く、別の画面（`/management/groups/suspended`）
* 停止中のグループを、停止日時の新しい順に並べる
* 列: グループ名、停止した時点の上位グループ、停止日時、停止した人
* 絞り込みの行（見出しと一覧の間）に、キーワードと「一緒に停止された下位グループも表示する」の
  チェックボックスを置く。条件は URL に残す（`?q=第一&include_descendants=1`）
  * **チェックなし（既定）**: 起点だけを出す。起点の行に「下位グループ ◯件も一緒に停止」と添える。
    キーワードの対象も起点だけ
  * **チェックあり**: 一緒に止まった下位も1行ずつ出し、「『営業本部』と一緒に停止」と添える。
    キーワードの対象も下位を含むすべて
  * チェックなしで見つからず、一緒に止まった下位には当てはまるものがあるときは、
    「一緒に停止された下位グループに ◯件あります」と出してチェックを入れる操作へ誘う
* キーワードの対象は、グループ名と、停止した時点の上位グループの名前
* 件数が増え続けるので、スクロールで続きを読み足す
* テナントの管理者にはすべてを出す。グループ管理者には、自分の範囲の中（自分が管理者である
  グループそのものを含む）だけを出す
* 選ぶと詳細（参照のみ）が開き、起点なら「再開する」で元に戻せる

# 利用者管理の仕様

管理の画面の「利用者管理」（`/management/users`）の決まり。テナントの管理者（オーナー・管理者）
だけが開ける。

# 利用者

* 利用者はテナントへの所属（`tenant_users`）。ログインのアカウント（`users`、メールアドレスと
  パスワード）はテナントをまたいで共通で、1つのアカウントが複数のテナントに所属できる
* 持つもの: 表示名、権限（オーナー・管理者・メンバー）、状態（招待中・有効・停止中・削除済み）
* テナントに入れるのは有効な人だけ（`doc/database.md` の「所属の有効性は入口でだけ判定する」）
* 利用停止と削除は、どちらも行を残す（論理削除）が、扱いが違う

  | | 利用停止 | 削除 |
  |---|---|---|
  | 戻せるか | 再開すれば元のとおり使える | 戻せない |
  | 見る手段 | 「利用停止中の利用者」の一覧と詳細 | 無い |
  | 所属グループ | 残す（グループの画面には出さない） | 外す |

# 画面

* 一覧には招待中・有効の人だけを出す。名前から詳細へ進む
* 詳細は参照だけ。見出しの横の「編集」から編集の画面へ進む
* 詳細の見出しは表示名で、メールアドレスを添える。状態は、招待中のときだけ名前の横に印で出す
  （有効なら出さない。停止中は下の「利用停止」の囲みで示す）。権限は行で出し、その下に所属グループの一覧を出す
  * 所属グループは、グループ名の下に最上位からの上位の並びを添え、その並びの順に並べる
  * グループ管理者のグループには「グループ管理者」の印を付ける
  * 利用停止中のグループは出さない（所属の行は残っていて、グループを再開すれば出る）
  * グループ名からグループ管理の詳細へ進める

# 追加

* 一覧の「利用者を追加」から、メールアドレス・表示名・権限・所属グループを入れて加える
* 追加した人は「招待中」になる。招待中の人はまだテナントに入れない（招待を受け取って有効にする
  仕組みは、まだ無い）
* 権限はメンバーか管理者から選ぶ。自分がオーナーのときは、オーナーも選べる
* 所属グループは有効なグループから複数選べる。「全員」（定義上全員が入る）と停止中のグループは
  出さない。グループ管理者の印はグループ管理の側で付ける
* 所属グループは、選んだものを行として並べ、「所属グループを追加」のダイアログで足す。ダイアログは
  グループ名で探す一覧で、各行のグループ名の下に上位の並びを出す（グループのメンバーの追加と同じ形）。
  候補も選んだ行も、上位の並びの順（グループ管理のツリーをたどる順）に並べる。
  行の「削除」で外す。どちらも「保存する」までは反映しない
  * いずれツリーから選ぶダイアログも要るかもしれないが、今は検索つきの一覧だけにしてある
* 同じメールアドレスのアカウントが他のテナントにあれば、そのアカウントに所属を足す。
  パスワードは変えない
* このテナントにすでにいる人（停止中も含む）は加えられない
* 削除済みの人を同じメールアドレスで加えると、新しい所属として加える（下の「削除」）

# 編集

* 変えられるのは、表示名・権限・状態・所属グループ。メールアドレス（アカウントのもの）は変えられない
* 権限
  * オーナーを付けられるのはオーナーだけ。オーナーの権限を変えられるのもオーナーだけ
  * 自分の権限は自分で下げられる。メンバーに下げると管理の画面を開けなくなるので、保存後はトップへ移る
* 状態
  * 編集で変えられるのは、招待中の人を有効にすることだけ。停止は下の「利用停止」の操作で行う
  * オーナーの状態を変えられるのはオーナーだけ
* 有効なオーナーが1人もいなくなる変更（最後のオーナーを管理者に下げる）は受け付けない
* 所属グループは、追加と同じダイアログで足し、行の「削除」で外す。外さずに残したグループでは、
  グループ管理者の印（グループ管理で付けたもの）は消えない。停止中のグループの所属は画面に出さず、
  編集でも変わらない
* 変えられない権限・状態は、選択肢ではなく文字で出す

# 利用停止

* 編集の画面の「利用停止」から確認の画面に移って止める（削除と同じく、誤って押さないよう詳細には置かない）
* 止められるのは有効な人だけ。招待中の人はまだテナントに入れないので、止める代わりに削除する
* 自分は止められない（締め出されないように）。オーナーを止められるのはオーナーだけ。
  有効なオーナーが1人もいなくなる停止は受け付けない
* 止めた日時と止めた人を残す
* 停止中の人は利用者の一覧に出さず、一覧の「利用停止中の利用者」から見る。新しく止めた順に並べ、
  表示名・メールアドレスで探せる
* 停止中の人は編集できない。詳細の囲みから「再開する」か「この利用者を削除」を行う
  * 再開すると有効に戻る。オーナーを再開できるのはオーナーだけ
* 所属グループ・ファイルの権限はそのまま残す。再開すれば元のとおりに効く

# 削除

* 編集の画面の「この利用者を削除」から確認の画面に移って消す（グループと同じく、誤って押さない
  よう詳細には置かない）。停止中の人は、詳細の囲みから消す
* オーナーと自分自身は削除できない
* 削除は所属の行を消さず、削除済みにする（論理削除）。行を消すとマイドライブも一緒に消え、
  ファイルの作成者などの記録も失われるため
* 削除すると所属グループからは外す。ファイルの権限の設定は残す（削除済みの人はテナントに
  入れないので使われない。共有設定の画面では「削除済み」と示す）
* 削除は戻せない。同じメールアドレスで加え直すと、元の所属は削除済みのまま残し、新しい所属を作る。
  マイドライブ・ファイルの権限・所属グループは引き継がない
* 確認の画面には、他の機能（ファイルなど）への影響は書かない（`doc/groups.md` の「削除」と同じ）

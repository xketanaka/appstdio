# 利用者管理の仕様

管理の画面の「利用者管理」（`/management/users`）の決まり。テナントの管理者（オーナー・管理者）
だけが開ける。

# 利用者

* 利用者はテナントへの所属（`tenant_users`）。ログインのアカウント（`users`、メールアドレスと
  パスワード）はテナントをまたいで共通で、1つのアカウントが複数のテナントに所属できる
* 持つもの: 表示名、アバター、ラベル、権限（オーナー・管理者・メンバー）、状態（招待中・有効・停止中・削除済み）
* ラベルは、外部から招いた人に「ゲスト」「◯◯会社」と付けるなど、利用者を見分けるのに使う。
  複数付けられる。付け方はグループのラベルと同じ（`doc/groups.md` の「ラベル」）だが、一覧は別に持つ
  （グループのラベルは候補に出ない）
* テナントに入れるのは有効な人だけ（`doc/database.md` の「所属の有効性は入口でだけ判定する」）
* 利用停止と削除は、どちらも行を残す（論理削除）が、扱いが違う

  | | 利用停止 | 削除 |
  |---|---|---|
  | 戻せるか | 再開すれば元のとおり使える | 戻せない |
  | 見る手段 | 「利用停止中の利用者」の一覧と詳細 | 無い |
  | 所属グループ | 残す（グループの画面には出さない） | 外す |

# アバター

* 丸い画像。表示名と同じく所属ごとに持つ（組織ごとに別の画像）。削除して加え直したときは引き継がない
* 未設定のときは、全員同じ人の絵を出す
* 設定・差し替えは本人だけ。個人設定で画像を選ぶと、丸の中に入れる範囲（位置と拡大率）を調整する
  ダイアログが開き、「設定する」で保存する
  * 受け付けるのは PNG・JPEG・GIF・WebP、10MB まで。形式は中身で判定する（SVG はスクリプトを
    埋め込めるので受け付けない）
  * サーバで、調整した範囲を切り抜き、256px 四方の WebP に縮めて保存する。元の画像は残さない
* 削除は本人（個人設定）と、テナントの管理者（利用者の編集の画面）ができる。管理者は不適切な画像を
  外すためのもので、差し替えはできない
* 画像は同じテナントの人だけが見られる。Active Storage の公開ルートは使わず、所属を確かめる
  コントローラ（`/avatars/:id/:version`）から出す。version は画像の版で、差し替えると URL が変わるので、
  ブラウザに長くキャッシュさせる
* 出す場所: 画面右上、利用者管理（一覧・詳細・編集・停止中の一覧）、グループ管理（所属メンバー・
  下位グループに所属するメンバー・メンバーの編集とその候補）、ファイルの共有設定（相手の一覧と候補）。
  停止中・削除済みの人も、設定してあれば出す

# 画面

* 一覧には招待中・有効の人だけを出す。名前の横にラベルを出す。名前から詳細へ進む
* 一覧の「所属グループ」には、有効な部署のグループの名前を、名前の順にカンマ区切りで出す。
  プロジェクトのグループと停止中のグループは出さない。上位の並びは添えない（詳細で見る）。狭い画面では列を出さない
* 詳細は参照だけ。見出しの横の「編集」から編集の画面へ進む
* 詳細では、所属グループ（部署）と分けて参加プロジェクトを出す（`doc/projects.md` の「利用者の画面」）
* 詳細の見出しは表示名で、メールアドレスとラベルを添える（ラベルが無ければ出さない）。状態は、招待中のときだけ名前の横に印で出す
  （有効なら出さない。停止中は下の「利用停止」の囲みで示す）。権限は行で出し、その下に所属グループの一覧を出す
  * 所属グループは、グループ名の下に最上位からの上位の並びを添え、その並びの順に並べる
  * グループ管理者のグループには「グループ管理者」の印を付ける
  * 利用停止中のグループは出さない（所属の行は残っていて、グループを再開すれば出る）
  * グループ名からグループ管理の詳細へ進める

# 追加

* 一覧の「利用者を追加」から、メールアドレス・表示名・ラベル・権限・所属グループを入れて加える
* 追加した人は「招待中」になり、招待メールを送る（下の「招待」）。招待中の人はまだテナントに入れない
* 権限はメンバーか管理者から選ぶ。自分がオーナーのときは、オーナーも選べる
* 所属グループは有効なグループから複数選べる。「全員」（定義上全員が入る）と停止中のグループは
  出さない。グループ管理者の印はグループ管理の側で付ける
* 所属グループは、選んだものを行として並べ、「所属グループを追加」のダイアログで足す。ダイアログは
  グループ名で探す一覧で、各行のグループ名の下に上位の並びを出す（グループのメンバーの追加と同じ形）。
  候補も選んだ行も、上位の並びの順（グループ管理のツリーをたどる順）に並べる。
  行の「削除」で外す。どちらも「保存する」までは反映しない
  * いずれツリーから選ぶダイアログも要るかもしれないが、今は検索つきの一覧だけにしてある
* 同じメールアドレスのアカウントが他のテナントにあれば、そのアカウントに所属を足す。
  パスワードは変えない
* このテナントにすでにいる人（停止中も含む）は加えられない
* 削除済みの人を同じメールアドレスで加えると、新しい所属として加える（下の「削除」）

# 招待

* 追加すると招待中になり、本人に招待メールを送る。招待メールは知らせるためのもので、参加するのに
  メールの URL を開く必要はない（パスワードがまだ無い新しいアカウントを除く）
* 参加のしかたはアカウントによって違う
  * パスワードのあるアカウント（ログインしたことがある）: ログインすると、組織の選択に招待中の組織が
    「招待されています」の印付きで出る。「参加する」を押すとその時点で有効になり、そのテナントに入る。
    招待メールにはログインの URL を書く。期限は無く、招待中のあいだはいつでも参加できる
  * 一度もログインしたことのないアカウント（招待で作られた新しいアカウント）: パスワードが無いので、
    招待メールの URL でパスワードを決めて参加する。参加すると有効になり、そのままログインしてそのテナントに入る
* 組織の選択では、所属が招待中の1つだけでも自動では入らない。選ぶことが参加になるので、本人が押すまで入れない
  （メールアドレスを打ち間違えて別の人を招待しても、その人が選ばない限り入らない）
* パスワードを決める URL の有効期限は、招待メールを送った日時から組織設定の日数（既定3日、1〜30日）。
  期限は URL を開いたときにその時点の設定で判定するので、日数を変えると送り済みの招待にも効く。
  期限が切れても、パスワードの再設定でパスワードを決めれば、ログインして組織の選択から参加できる
* 招待中の人の詳細に、招待メールを送った日時と、新しいアカウントなら URL の有効期限（切れていればその旨）を出し、
  「招待メールを再送」を置く。再送すると、前に送った URL は使えなくなる
* 招待の URL を開いた画面はログインしていなくても開ける。開いた人によって出し分ける
  * ログインしていなくて、新しいアカウント: パスワードを決めて参加する
  * ログインしていなくて、パスワードのあるアカウント（送ったあとにパスワードを決めた場合）: ログインして組織の
    選択から参加するよう案内する
  * 招待された本人でログインしている: 組織の選択から参加するよう案内する
  * 別のアカウントでログインしている: ログアウトしてから開き直すよう案内する
* パスワードを決めて参加すると、メールを受け取れたのでメールアドレスを確かめたことにする
* 使えない URL（期限切れ・再送より前のもの・参加済み・削除済み・改ざん）は、どれも同じ案内
  （「この招待は使えません」。管理者に再送を頼むよう促す）を出す
* URL のトークンは署名付きで、テナントの id・所属の id・送った日時を持つ。招待の画面はログイン前で
  テナントが決まっていないので、トークンのテナントに切り替えてから所属を探す

# パスワードの再設定

* アカウント（`users`）ごとの機能で、テナントは関係しない。ログインの画面に「パスワードを忘れた場合」を置く
* メールアドレスを入れると、新しいパスワードを決める URL をメールで送る。登録の無いメールアドレスでも
  同じ案内（「登録されていれば送りました」）を出し、登録の有無を知らせない
* URL は30分で使えなくなる。パスワードを変えると、それより前に送った URL もすべて使えなくなる
  （トークンはパスワードの salt を含めて署名している。Rails の `has_secure_password` の再設定トークン）
* 新しいパスワードを保存すると、そのままログインする。メールを受け取れたので、メールアドレスを確かめたことにする
* 使えない URL（期限切れ・変更済み・改ざん）は、どれも同じ案内を出し、再設定のメールを送り直すよう促す
* 同じ接続元からのメールの送信は、3分に5回まで（他人のメールアドレスへ送りつけるのを遅らせる）

# 編集

* 変えられるのは、表示名・ラベル・権限・所属グループ。メールアドレス（アカウントのもの）は変えられない
* 権限
  * オーナーを付けられるのはオーナーだけ。オーナーの権限を変えられるのもオーナーだけ
  * 自分の権限は自分で下げられる。メンバーに下げると管理の画面を開けなくなるので、保存後はトップへ移る
* 状態は編集では変えない。有効にするのは本人が招待を受けたとき（上の「招待」）、停止は下の「利用停止」の操作
  * 以前は管理者が招待中の人を有効にできたが、招待で作った新しいアカウントはパスワードを誰も知らず、
    有効にしてもログインできないのでなくした
* 有効なオーナーが1人もいなくなる変更（最後のオーナーを管理者に下げる）は受け付けない
* 所属グループは、追加と同じダイアログで足し、行の「削除」で外す。外さずに残したグループでは、
  グループ管理者の印（グループ管理で付けたもの）は消えない。停止中のグループの所属は画面に出さず、
  編集でも変わらない
* 変えられない権限は、選択肢ではなく文字で出す

# 利用停止

* 編集の画面の「利用停止」から確認の画面に移って止める（削除と同じく、誤って押さないよう詳細には置かない）
* 止められるのは有効な人だけ。招待中の人はまだテナントに入れないので、止める代わりに削除する
* 自分は止められない（締め出されないように）。オーナーを止められるのはオーナーだけ。
  有効なオーナーが1人もいなくなる停止は受け付けない
* 止めた日時と止めた人を残す
* 停止中の人は利用者の一覧に出さず、一覧の「利用停止中の利用者」から見る。新しく止めた順に並べ、
  表示名・メールアドレスで探せる
* 停止中の人は編集できない。詳細の囲みから「再開する」か「この利用者を削除」を行う
  * 再開すると有効に戻る。オーナーを再開できるのはオーナーだけ
* 所属グループ・ファイルの権限はそのまま残す。再開すれば元のとおりに効く

# 削除

* 編集の画面の「この利用者を削除」から確認の画面に移って消す（グループと同じく、誤って押さない
  よう詳細には置かない）。停止中の人は、詳細の囲みから消す
* オーナーと自分自身は削除できない
* 削除は所属の行を消さず、削除済みにする（論理削除）。行を消すとマイドライブも一緒に消え、
  ファイルの作成者などの記録も失われるため
* 削除すると所属グループからは外す。ファイルの権限の設定は残す（削除済みの人はテナントに
  入れないので使われない。共有設定の画面では「削除済み」と示す）
* 削除は戻せない。同じメールアドレスで加え直すと、元の所属は削除済みのまま残し、新しい所属を作る。
  マイドライブ・ファイルの権限・所属グループは引き継がない
* 確認の画面には、他の機能（ファイルなど）への影響は書かない（`doc/groups.md` の「削除」と同じ）

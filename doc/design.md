# 画面デザインの指針

画面の見た目の決まり。新しい画面を作るときも、既存の画面を直すときも、ここに従う。
CSS の書き方の仕組み（Tailwind の構成、開閉する UI の作り方など）は `doc/architecture.md` の「CSS」を参照。

## 方向性

**Google Workspace（ドライブ・Gmail）寄りの、やわらかく親しみやすい業務画面。**

汎用の業務サービスなので、強い個性は持たせない。そのうえで「素の Tailwind」に見える安っぽさを
避ける。3つの案（shadcn 寄り・Google 寄り・freee 寄り）を同じ画面で描いて比べ、この方向に決めた。

- 薄く青みのある**地**の上に、角の大きい**白いパネル**を浮かせる。ヘッダーと左ペインは地と一体にする
- 色は**やわらかい青を1色**だけ使う。選択中の項目と主要なボタンに限る
- 角は丸く、ボタンと選択中の項目は**丸い帯**の形にする
- 線は少なく薄く。区切りは線より余白と面の違いで示す
- 見出しは大きく**細め**（太字にしない）

## 色

`app/javascript/entrypoints/application.css` の `@theme` に定義してある。

| 用途 | 使うもの |
|---|---|
| 画面の地（ヘッダー・左ペインの背景、表の行のホバー） | `canvas`（`#f3f6fb`） |
| 本文のパネル・ポップアップ | `white` |
| 主要なボタン | `primary-600`、ホバーは `primary-700` |
| 選択中の項目の面と文字 | `primary-100` と `primary-900` |
| リンク・副ボタンの文字 | `primary-700` |
| 文字 | `slate`（本文 `800`、メニューの項目 `700`、補足 `500`、使えない項目 `400`） |
| 線 | 表の見出しの下 `slate-200`、行の境目・パネル内の区切り `slate-100` |
| 地の上のホバー | `slate-900/5`（半透明なので、ヘッダーの色が変わっても使える） |
| 状態 | 成功 `green` / 注意 `amber` / エラー・削除 `red`。特権モードは `amber` |

色を足したくなったら、まず上のどれかで表せないか考える。`primary` 以外の色相を飾りに使わない。

## 文字

書体は Noto Sans JP（`doc/architecture.md` の「CSS」）。

| 用途 | クラス |
|---|---|
| パネルの見出し（`h1`） | `text-title`（22px）。太字にしない |
| 左ペインの機能名、ヘッダーのタイトル | `text-lg font-medium` |
| 本文・表・入力欄・ボタン | `text-sm`（14px） |
| 補足・表の見出し・ヒント | `text-xs`（12px） |

太さは `font-medium`（500）と `font-semibold`（600）までにする。`font-bold` は使わない。
強調は太さより、色（`slate-500` と `slate-800` の差）と大きさで付ける。

## 形

| 対象 | 角丸 |
|---|---|
| ボタン、左ペイン・メニューの項目、バッジ、アイコンだけのボタン | `rounded-full` |
| 入力欄、フォームのエラー表示、パネル内の補足の囲み | `rounded-xl` |
| 本文のパネル、アカウントのポップアップ、注意・完了のメッセージ | `rounded-2xl` |
| 行の操作メニュー（小さいポップアップ） | `rounded-xl` |
| ログインのカード | `rounded-3xl` |

影は**浮いているものだけ**に付ける（ポップアップ `shadow-lg`、スライドメニュー `shadow-xl`）。
ボタン・入力欄・パネルには付けない。パネルは地との色の差で浮かせる。

## 部品

ボタン・入力欄・左ペインの項目は、部品のクラスとして `app/javascript/entrypoints/application.css` の
`@layer components` に定義してある。ERB でも Vue でも同じクラスを書く。同じ見た目のものを書くときは必ず使う。

| 部品 | クラス |
|---|---|
| 主要なボタン | `btn btn-primary` |
| 副ボタン | `btn btn-secondary` |
| 削除のボタン | `btn btn-danger` |
| 小さいボタン | 上に `btn-sm` を足す（例 `btn btn-secondary btn-sm`） |
| 入力欄 | `input` |
| 左ペイン・メニュー・ツリーの1行 | `nav-item`。選択中は `nav-item-current` を足す |

```erb
<%= f.submit t("actions.save"), class: "btn btn-primary" %>
<%= link_to label, path, class: class_names("nav-item", "nav-item-current": current) %>
```

```vue
<button class="btn btn-primary btn-sm">…</button>
<div class="nav-item" :class="{ 'nav-item-current': current }">…</div>
```

- 主要なボタンは、1つの画面（パネル）に1つまで
- 位置や幅の調整はユーティリティを足す（`btn btn-primary w-full`、`nav-item ml-5 py-1.5`）。
  部品のクラスはユーティリティより下の層にあるので、足したユーティリティが必ず勝つ
- **部品のクラスを増やすのは、ERB と Vue の両方で使う、この文書で形を決めた部品だけ。**
  1つの画面でしか使わない組み合わせはクラスにしない

## 画面の骨格

```
body（canvas）
├ ヘッダー        地と一体。下線を引かない
├ 左ペイン        地と一体（2ペインの画面だけ）。w-64、選択中の項目は丸い帯
└ 本文のパネル    白、rounded-2xl。画面の右と下に 16px（スマホは 8px）の地を残す
```

**ページ全体はスクロールしない。** `body` が `overflow-hidden` なので、**各ビューが自分で
スクロール領域を作る**。`min-h-0` を付け忘れると、flex の子が内容の高さまで伸びて
スクロールせずにはみ出すので注意。

パネルはレイアウトが用意する。2ペインの画面は `layouts/two_pane` の右側、それ以外の
ログイン後の画面は `layouts/application` が本文全体をパネルにする。ビューはパネルの中身だけを書く。
ログインの画面はパネルにせず、地の上にカードを置く。

ビューの書き方は2通り。

```erb
<%# 一覧など画面を埋めるもの。見出しは固定し、中身だけスクロールさせる %>
<div class="shrink-0 px-6 pt-5 pb-3"><h1 class="text-title">見出し</h1></div>
<div class="min-h-0 flex-1 overflow-auto px-3">表（セルは px-3）</div>

<%# フォームや詳細。読みやすさのため最大幅を設ける %>
<div class="min-h-0 flex-1 overflow-y-auto">
  <div class="mx-auto w-full max-w-3xl px-4 py-6 sm:px-6 sm:py-8">本文</div>
</div>
```

- 見出しの `px-6` と、表の `px-3` + セルの `px-3` で、見出しと表の文字の左端がそろう
- 見出しの行には下線を引かない。区切りは表の見出し行の線だけにする
- 表の絞り込み（キーワード・状態など）は、見出しの行には入れず、見出しと表の間に専用の行を
  設ける。見出しの行は「今いる場所と、そこへの操作（作成など）」、絞り込みの行は
  「表の見え方を変える操作」と役割を分ける。この行もスクロールさせない（`shrink-0`）

### 表

| 部分 | 書き方 |
|---|---|
| 見出し行 | `sticky top-0 bg-white text-xs text-slate-500`、セルは `px-3 py-2.5 font-medium`、下線 `slate-200` |
| 行 | 境目 `border-slate-100`、ホバー `bg-canvas` |
| 選択中の行 | `bg-primary-100`（左ペインの選択中の項目と同じ面） |
| ドラッグ中の落とし先 | `bg-primary-50` に `outline-2 outline-primary-600` の枠。一覧の行・左ペインの項目・パンくずで同じ |
| 選択中の見出し行 | 列の見出しの代わりに、選んだものへの操作（件数・解除・移動など）を出す。別の行に出すと一覧が下へずれ、ダブルクリックの2回目が別の行に当たる |
| 行の操作メニュー | 縦三点のアイコンボタン（`rounded-full`）から開く |

### ツリーに項目を足す操作

ツリー（グループなど）に項目を足す操作は、**どこに足すかが位置で分かる**ように置く。
画面の上段に「追加」の主要ボタンを1つ置き、選択中の項目の下に作る、という形にはしない
（何の下に作られるかが見えず、主要ボタンが画面に2つ並ぶ）。

| 置き場所 | 作られる場所 | 見た目 |
|---|---|---|
| ツリーの末尾 | 最上位 | 左ペインの項目と同じ行（`nav-item`）に「＋ ◯◯を追加」。文字は `slate-500` |
| ツリーの各行の右端 | その行の下 | 「＋」のアイコンボタン。マウスを載せた行（`group/row`）とキーボードで移ってきたときだけ出す。スマホ幅では出さない |
| 選んだ項目の詳細の画面 | その項目の下 | 見出しの横に副ボタン（`btn btn-secondary btn-sm`） |

スマホ幅ではホバーが無いので、行ごとの「＋」の代わりに詳細の画面のボタンを使う。

### 画面の下の知らせ

操作の結果（移動した、移せなかった、など）は、画面の左下に一時的に出す（数秒で消える）。
Google ドライブのスナックバーと同じ扱い。`rounded-xl`、`shadow-lg`、文字は白、面は通常 `slate-800`、
失敗は `red-700`。ダイアログの中で起きた入力の誤りは、知らせではなくダイアログの中に出す。

## ヘッダーの例外

- **組織設定**: 利用テナント側のヘッダーは、組織設定で背景色（タイトルカラー）とロゴを変えられる。
  背景色は `style` で指定し、未設定なら `canvas`。暗い色のときは文字を白にする
  （`TenantSetting#light_title_color?`）。ブランドの印（`primary` の丸）はロゴの枠で、
  ロゴがあれば置き換わり、無ければ表示中のタイトルの1文字目を出す
- **運営者画面**: ヘッダーを暗い色（`slate-900`）にする。利用テナント側の画面と取り違えないため。
  地とパネルは利用テナント側と同じ

## 新しい画面を作るとき

1. 骨格（パネルの中身だけを書く、一覧か詳細か）を上の2通りから選ぶ
2. ボタン・入力欄・左ペインの項目は部品のクラス（`btn` / `input` / `nav-item`）を使う
3. 色・角丸・文字の大きさは、この文書の表にあるものだけを使う
4. スマホ幅（390px 程度）でも崩れないか確かめる（`doc/architecture.md` の「PC とスマホの両対応」）

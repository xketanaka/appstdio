# プロジェクト管理の仕様

管理の画面の「プロジェクト管理」（`/management/projects`）の決まり。テナントの管理者（オーナー・管理者）
だけが開ける。組織設定で「プロジェクト機能を利用する」にしたときだけ使える。

# プロジェクトとグループ

* プロジェクトは、グループ（`groups.kind = project`）と1対1で結びつく（`projects.group_id`）。
  名前・ラベル・メンバー・利用停止の状態は、グループのものをそのまま使う
  * プロジェクトにだけある項目は、まだ無い（名前だけ）。増えたら `projects` に持たせる
* プロジェクトのグループは、最上位のグループ「プロジェクト」（`kind = project_root`）の直下に置く
  * 「プロジェクト」は、プロジェクト機能を「利用する」にしたときにシステムが作る。テナントに1つ
  * 同じ名前の最上位のグループ（部署）があると作れないので、そのときは「利用する」にできない
* プロジェクトのメンバーは、グループのメンバーとして持つ。グループ管理者の印を付けた人が
  プロジェクト管理者
* ファイルの共有では、部署のグループと同じく相手に選べる（「プロジェクト」そのものは選べない）

# 部署との違い

コードの上でも、グループの種類（`kind`）で部署（`department`）と区別する。

| | 部署 | プロジェクトのグループ | 「プロジェクト」 |
|---|---|---|---|
| 作る・名前を変える | グループ管理 | プロジェクト管理 | システム（変えられない） |
| ラベル・メンバーの編集 | グループ管理 | プロジェクト管理・グループ管理 | できない |
| 利用停止・再開・削除 | グループ管理 | プロジェクト管理 | できない |
| 下位グループ・移動 | できる | できない | 下にはプロジェクトのグループだけ |
| 部署の上位に選ぶ | できる | できない | できない |

* グループ管理のツリーでは、部署の後ろに「プロジェクト」とその下のプロジェクトのグループを出す
* プロジェクト管理者は、今のグループ管理者と同じく、グループ管理から自分のプロジェクトの
  メンバーとラベルを編集できる

# 画面

* 一覧には有効なプロジェクトを出す。列はプロジェクト名（ラベルを添える）、プロジェクト管理者、人数
  （利用停止中の人は数えない）。名前から詳細へ進む
* 詳細は参照だけ。名前・ラベルと、メンバーの一覧を出す。「編集」で名前・ラベルの編集へ、
  「メンバーを編集」でメンバーの編集へ進む
* 作ったら、続けてメンバーの編集に移る（グループと同じ）
* プロジェクト名は、有効なプロジェクトの間で重ならないようにする
* メンバーの編集は、グループ管理のメンバーの編集と同じ部品（ダイアログで探して足す）

# 利用停止

* 編集の画面の「利用停止」から確認の画面に移って止める。グループも一緒に止まる
* 停止中のプロジェクトは編集・削除できない（消したいときは再開してから消す）。一覧に出さず、
  一覧の下の「利用停止中のプロジェクト」から見る。詳細の「再開する」で戻す
* 同じ名前の有効なプロジェクトがあるときは再開できない
* グループ管理からは、プロジェクトのグループを停止・再開できない

# 削除

* 編集の画面の「このプロジェクトを削除」から確認の画面に移って消す。グループも一緒に消え、
  ファイルの共有設定も消える（グループの削除と同じ）
* 確認の画面には、他の機能への影響は書かない（`doc/groups.md` の「削除」と同じ）

# 利用者の画面

* 利用者の詳細では、所属グループ（部署）と分けて「参加プロジェクト」を出す。利用者の一覧には出さない
  （数が多くなりやすいため）
* 利用者の追加・編集では、所属グループと別の欄で参加プロジェクトを選ぶ

# 利用しないに戻したとき

* メニュー（プロジェクト・プロジェクト管理）から消し、プロジェクト管理の画面を開けなくするだけ。
  プロジェクト・グループ・メンバー・ファイルの共有設定はそのまま残し、権限もそのまま効く
* グループ管理のツリーには、そのまま出る
* 利用者の詳細・追加・編集では参加プロジェクトの欄を出さない。編集で保存しても、参加プロジェクトは変えない
